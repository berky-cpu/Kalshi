## Design
Replays recorded raw through the recorders' own `MessageProcessor`s (reusing `health.make_processor` +
seeding), emits **event-driven top-N L2 snapshots** (one per top-N change, `recv_ts_ns` + monotonic
`snap_id`), prices as parquet `Decimal(38,8)` from exact transmitted strings. Datasets: books, kalshi_books,
trades, settlements. The L3→L2 aggregation is correct and hand-tested.

## Round 1 — FAIL
- **F1/F3 [CRITICAL]** Kraken "gold" checkpoint was **circular** — the fixture checksum was self-generated by
  `kraken_crc32`, so it proved self-consistency, not a match to real venue truth.
- **F2/F4 [CRITICAL]** **Partial books written indistinguishably from complete ones** — the REST baseline
  snapshot is applied in memory but never persisted by the recorder, so WS-only replay yields incomplete
  Coinbase/Binance/Bitstamp books with no completeness marker; post-gap/mismatch books emitted unmarked.
- F5 (zero-size phantom L2 levels), F6 (`exch_ts_ns` via float), F7 (as-of tie-break undoc).

## Round 2 — PASS
- **F1/F3 FIXED (genuinely non-circular):** a new test runs Kraken's REAL L3-guide worked-example input
  (21 bids/14 asks, published checksum **`1063832831`**, externally anchored in docs/feeds.md + facts.md from
  a prior commit) through `normalize_crypto` and asserts the checkpoint matches, and that the emitted top-N L2
  is the faithful aggregation of that validated book. The reviewer **reimplemented the CRC from scratch** and
  reproduced `1063832831`. The old fixture-checksum test is relabeled a regression check; the stale base.py
  "UNVERIFIED" comment corrected to VERIFIED.
- **F2/F4 FIXED:** a `synced` boolean on BOOK_SCHEMA/KALSHI_BOOK_SCHEMA = `baseline_established AND NOT
  pending_resync`. Baseline flips True only on a RECORDED complete snapshot (Kraken/Bybit `snapshot`, Kalshi
  `orderbook_snapshot`); Coinbase/Binance/Bitstamp (REST baseline not recorded) stay `synced=False` throughout
  — a partial book can never show True. `pending_resync` flips True on `needs_resnapshot`, clears on the next
  recorded snapshot, so post-mismatch books are flagged. Rows are never dropped, only marked; the marker can't
  alter book content. Verified end-to-end through parquet.
- **F5/F6/F7 FIXED:** zero-size levels filtered before top-N (re-indexed); `exch_ts_ns` integer-exact; as-of
  `(recv_ts_ns, snap_id)` tie-break documented.

## Standing items (honestly flagged, non-blocking for 2.1)
- **Recorder must persist REST snapshots (→ new ROADMAP item):** Coinbase/Binance/Bitstamp book completeness
  can't be exactly reconstructed or checkpointed offline because the recorder never writes the REST baseline
  to the stream. Surfaced correctly as `synced=False` in the data (downstream 2.2 can filter) — but to get
  COMPLETE constituent books from the live VPS run, the recorder must write the REST snapshot into the
  recording. Required before relying on those three venues' books.
- **Bybit** checkpoint stays informational (a snapshot is a reset carrying newer data); **Kalshi** schema +
  **Binance aggTrade** `m`→taker mapping remain UNVERIFIED (1.1b / feeds.md F-2), flagged in code.
- Normalizer buffers rows in memory per feed (fine at this scale; chunked writes a later optimization).
